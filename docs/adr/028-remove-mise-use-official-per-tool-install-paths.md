# ADR-028: mise を撤去しツールごとの公式導入経路を使用する

## Status

Proposed

## Context

ADR-002/003/013/021/022/027 は mise を前提に、shim の symlink 化、lockfile 同期、対象プラットフォーム固定、pnpm の直接管理、公式成果物からの導入といった判断を積み重ねてきた。しかし mise は汎用ツールマネージャーであり、各ツールの公式インストール経路とは別の抽象層・状態（shim、lockfile、バージョン解決ロジック）を持ち込む。この抽象層は ADR-009/016 のように言語ツールチェイン固有の解決順序と衝突し、ADR-027 のように OS ごとの導入機構の差異を吸収するための追加判断を要求し続けてきた。

mise という共通レイヤーを維持する限り、個々のツールの公式な導入・更新・検証手順との差分を横断的に管理し続けるコストが発生し、mise 自体のバージョン管理・shim 経路・lockfile 整合性が独立した関心事として残り続ける。

## Decision

mise を段階的に完全撤去する。撤去後は、ツールごとに以下の優先順位で導入経路を個別に選ぶ。

- OS/ベンダーの標準パッケージマネージャー
- 各ツールの upstream が推奨するインストーラー・スクリプト・専用バージョンマネージャー
- 検証済みの公式リリース成果物
- 言語エコシステム標準のコマンド

導入は既存の chezmoi run scripts（`run_once_before_*` / `run_once_after_*` / `run_onchange_after_*` 等）と `home/.chezmoidata.toml` の desired declarations の枠組みを用いて表現する。mise のような汎用マネージャー・shim・proxy への実行時依存は持たない。撤去にあたっても、汎用マネージャーを代替する独自 CLI、状態 DB、コンテンツアドレスキャッシュ、生成機構、PATH フラグメント、汎用インストーラーフレームワークは新設しない。macOS/Linux/Windows/WSL の 4 環境でユーザー向けの機能等価性を維持する。

ADR-002/003/013/021/022/027 は本 ADR による撤去方針の対象であるが、mise 撤去が完了するまでは各 ADR が定める挙動が有効であり続けるため、Status は変更しない。撤去完了時に個別に Deprecated / Superseded を判断する。

## Consequences

ツールごとの導入経路が公式ドキュメントと一致し、mise の shim・lockfile・バージョン解決に起因する間接的な不整合（ADR-009/016 のような衝突）が構造的に発生しなくなる。一方、ツール数だけ導入経路の実装・保守が個別化し、mise が担っていた「単一コマンドでの一括更新・一覧」という利便性は失われる。既存の chezmoi run scripts と `home/.chezmoidata.toml` を単位として移行するため、ツールごとの移行は独立した変更として段階的に進められるが、移行完了までは mise 関連 ADR と本 ADR の方針が並存する。
